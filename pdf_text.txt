Технічні Вимоги та Стек
1. Базові Технології: Java 21+, Maven/Gradle.

2. Фреймворки: Spring Boot 3+, Spring Data JPA, Spring Web.
3. База Дбаних: В якості сховища даних необхідно
використовувати реляційну базу даних (наприклад, PostgreSQL).
4. Сховище: Дані повинні зберігатися у базі даних. Зберігання
даних у пам'яті програми (in-memory storage) не допускається.
5. Архітектура: Обов'язкове використання багатошарової
архітектури:
​ Controller Layer (REST API endpoints).
​ Service Layer (Бізнес-логіка, GPA-обчислення, фільтрація).
​ Repository Layer (Взаємодія з БД через Spring Data JPA).
6. Взаємодія: Застосунок повинен надавати тільки REST API.
Розробка фронтенду (UI) не вимагається.

Нефункціональні Вимоги
1. REST Конвенції — Чітке дотримання принципів REST:
використання множини в URL (e.g., /students), коректні
HTTP-статуси (200 OK, 201 Created, 400 Bad Request, 404 Not
Found), обробка параметрів запиту.
2. DTOs (Data Transfer Objects) — Обов'язкове використання DTO
для передачі даних між Controller та клієнтом (уникайте прямої
передачі JPA-сутностей).
3. Документація (Swagger) — ОБОВ'ЯЗКОВО: Інтеграція
Springdoc-OpenAPI для автоматичної генерації документації API
(Swagger UI). Всі ендпоінти мають бути коректно описані.
4. Обробка помилок — Централізована обробка винятків за
допомогою @ControllerAdvice для повернення зрозумілих
HTTP-помилок (наприклад, 400 Bad Request при невалідному
вводі даних або 404 Not Found при відсутності сутності).
5. Тестування — ОБОВ'ЯЗКОВО: Проєкт повинен містити
покриття тестами.

Почни з JPA: перш ніж писати контролери, налаштуй JPA та
переконайся, що ти можеш зберігати та отримувати прості

Сфокусуйся на REST: визнач, які DTO тобі потрібні для
вхідних даних (Requests) та вихідних (Responses).

Напиши простий інтеграційний тест для контролера після
того, як реалізуєш перший CRUD.

максимально використовуй можливості Spring Data JPA
(наприклад, findByStatusAndYear()) замість ручної реалізації
